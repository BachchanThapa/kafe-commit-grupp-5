## Theory Questions

### 1. What is Agile Development, and how was our work Agile?

Agile development means working in small steps, collaborating, and improving through feedback. We worked with User Stories, daily standups, Pull Requests, and code reviews to complete our sprint.

### 2. Which Scrum roles and activities did we use?

We had a Scrum Master and Developers. The Scrum Master helped organize the work and communication. We used sprint planning, daily standups, and a retrospective to coordinate and improve our teamwork.

### 3. How did a User Story move from To Do to Done?

We selected a User Story from our Kanban board and moved it to In Progress. Then we created a feature branch, wrote the code, and opened a Pull Request. After that, we moved the story to Review and notified the team in our Discord channel. Another team member reviewed, approved, and merged the code into main. Finally, we moved the User Story to Done.

### 4. What is a merge conflict, when does it happen, and how do we solve it?

A merge conflict happens when Git cannot automatically combine changes from different branches, for example when two developers edit the same line in `index.html`.

We did not have any merge conflicts because each team member worked on their own assigned function in index.html.

However, if a conflict occurs, for example, if two developers change funktion04() differently in index.html, Git may not be able to merge the changes automatically. We can resolve the conflict by choosing which changes to keep, editing the conflicting code, marking the conflict as resolved, and completing the merge.
