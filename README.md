## Teorifrågor

### 1. Vad är agil utveckling, och vad i ert arbetssätt den här veckan var agilt?

Agil utveckling innebär att man arbetar i små, korta steg och anpassar sig efter feedback i stället för att planera allt i förväg. Under veckan var det agilt att vi delade upp arbetet i små user stories, jobbade i korta iterationer och flyttade korten på tavlan efter hand. Vi justerade också planen när nya stories dök upp och lät varje ändring granskas och mergas separat.

### 2. Vilka Scrum-roller och moment använde ni (till exempel Scrum Master, daily, sprint och retrospektiv)? Beskriv hur de fungerade i er grupp.

Vi hade en Scrum Master, Bachchan, som höll koll på tavlan och hjälpte gruppen att komma vidare, medan övriga var utvecklare. Vi använde sprintplanering, dagliga standups och en retrospektiv i slutet av veckan. Det fungerade bra eftersom alla hade egna stories och vi snabbt kunde stämma av vad som var gjort, vad som var nästa steg och om någon satt fast.

### 3. Beskriv hur en user story gick från Att göra till Klart hos er, med branch, Pull Request, review och merge.

En story började som ett kort i Att göra och flyttades till Pågår när arbetet startade. Vi skapade en egen branch, ändrade bara rätt funktion i index.html och pushade branchen. Därefter öppnade vi en Pull Request där en annan person granskade och godkände, och först efter review mergades den till main och kortet flyttades till Klart.

### 4. Vad är en merge-konflikt, när uppstår den och hur löser man den på GitHub? Ge ett exempel med en funktion i index.html. Om ni fick en konflikt under veckan, beskriv den.

En merge-konflikt uppstår när två branches har ändrat samma rad i samma fil och Git inte kan avgöra vilken version som ska gälla. Det kan till exempel hända om två personer ändrar samma funktion i index.html, som `funktion03`, på olika branches. På GitHub löser man konflikten genom att hämta senaste main till sin branch, välja rätt kod, ta bort konfliktmarkeringarna och sedan committa och pusha igen. Vi fick ingen konflikt den här veckan eftersom vi höll oss till olika funktioner och hämtade senaste main innan vi pushade.
